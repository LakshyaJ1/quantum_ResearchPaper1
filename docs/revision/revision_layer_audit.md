# Revision scenario and metric audit

This read-only review covers revision/scenarios.py, revision/metrics.py, their tests, and the experimental runner as inspected on 26 September 2026. Only the separately approved pure-function memoization in qkdsim/physics.py was changed during this review. The root agent owns scenario, metric and runner implementation.

The source/super-sink weighted cut construction correctly joins every terminal with an artificial edge whose capacity exceeds the total cost of all real edges. Its real crossing edges therefore define an all-terminal cut; summing the cut costs does not double-count undirected edges. The formation's all-terminal cut cost is two under the relative fibre-cost assumption of ten. This differs from the historical two-edge betweenness selection, which left one post reachable. A weighted cut is exact for structural isolation cost, not an optimizer of finite-horizon assurance harm. For a budget smaller than the full cut, consuming an ordered prefix is a heuristic rather than an optimal partial cut.

Static betweenness and recomputed residual-graph betweenness divide their scores by assumed edge costs. The latter is computed once during construction while successively deleting hypothetical edges. It should be described as recomputed targeting, not an online adaptive attacker observing actual inventories. Fibre costs 1/10/100 are explicitly relative stress-test inputs, not estimated attack energy or monetary costs. The attack budget counts simultaneously selected links weighted by these costs; duration is a separate axis and does not multiply budget in the current model.

Environmental draws have fixed dimensions at every tick. Attack membership and controller decisions do not skip RNG draws, so attacked and clean counterfactuals on the same topology and seed retain identical exogenous transport/generation streams. Arrival and endpoint streams remain separately seeded. The correlated model shares one FSO generation process, while transport remains independently generated for every link. That is a useful controlled correlation experiment with the same specified marginal transition rates; it does not model measured terrain or prove realistic weather dependence. A change in topology changes the number and identity of edge draws, so cross-topology pairing should be by scenario seed for reproducibility, not claimed as identical physical realizations.

Generation suppression and transport denial are correctly separated. Attack release restores normal generation without erasing inventory when buffer_policy is retain. The conservative purge alternative discards spendable inventory once on each transition from positive generation to non-generation. This includes environmental generation failures and transport outages, not just QBER abort or proven key compromise. It deliberately preserves the authentication reserve. Those details must be stated; this is not a claim that hardware universally purges keys in those circumstances. Lost stock is separately accumulated as sim.purged_bits and included in discarded_bits for reservoir conservation, rather than being counted as useful consumption.

The purge counter is a full-run counter, including warmup and deadline drain. It should only be compared with full-run accounting, unless the runner adds an explicit measurement-window purge counter. The core event-window accounting already captures purge via the store discard increments. _previous_generation_failure tracks sustained failures, preventing a repeated purge on every down tick. A zero-rate scenario also triggers a transition at the first tick under purge, which is part of this declared conservative model.

The preplaced_symmetric fallback only removes the abstract 0.35-second setup delay. It does not model finite pre-shared key stock, refresh overhead, KEM computation, data-plane congestion or packet authentication. G4 is therefore a computational-fallback policy label in these scenarios, rather than proof that ML-KEM actually ran. The root agent confirmed this is intentionally an idealized computational fallback comparison and should be described as such in the manuscript.

The metric numerators use timely served requests and the denominators use arrivals in the selected cohort. Qualified service and degraded service partition timely service; blocked/non-timely share complements availability. The entitled-ITS, forced-entitled and entitled-blocked shares use a common all-entitled-arrivals denominator. Payload fractions weight actual requested payload bits and avoid comparing a 256-bit rekey request with a 144-kbit OTP demand as equal byte exposure. Conditional forced fraction is kept separately labelled. The utility availability minus 0.75 times degraded-arrival-fraction uses consistent denominators, though 0.75 remains an explicit operator preference, not an empirical value.

After the core deadline drain, all requests are served or blocked, and the metric treatment is coherent. If summarize is used on provisional Results, it currently calls pending and late requests blocked through n minus timely served. That usage requires either waiting for completion or reporting a distinct unresolved/non-timely count. The default summarize end is unbounded rather than Results.horizon_s; this produces no discrepancy for a normal completed simulator run because there are no post-horizon arrivals. Future external Results producers must respect the same cohort definition.

Paired bootstrap checks equal one-dimensional array shape, at least two pairs, and finite differences; undefined denominators cause an explicit failure instead of being silently dropped. Matching seed identities is the caller's responsibility because the function receives arrays, not seed-labelled rows. The aggregator should join by seed and verify the same case/controller pairing before calling it. Intervals quantify realization uncertainty for the tested assumptions; they do not validate the scenario model. Mean intervals constructed against zero use the same bootstrap correctly.

Hourly low-ISR windows can have zero denominators. The runner currently writes Python NaN through allow_nan=True, which Python can read but strict JSON consumers reject. For a portable archival schema, undefined values should be null with numerator/denominator counts retained. This is an interoperability issue, not a reason to replace undefined outcomes with zero. Case construction also assumes valid positive durations/rates/reservoir scale/cost; the fixed planned grids satisfy this, but arbitrary future CLI/API use would benefit from explicit validation.

`python -X faulthandler -m pytest -q tests/test_revision_scenarios.py tests/test_revision_metrics.py` completed with exit 0 and eleven tests passing in 0.84 seconds. Tests cover the declared topology connectivity, weighted cut, generation-versus-transport distinction, attack/environment pairing, release behavior, purge-once semantics, arrival/payload denominators and paired intervals.

The profiling command ran one 3600-second scenario and recorded 1,347,764 calls in 0.789 seconds. rate_fraction consumed 0.273 seconds cumulatively across 46,142 calls. The bounded lru_cache(maxsize=256) optimization is safe because the function is pure and PhysicsConfig is frozen. The audit compares the full serialized Results object, not just aggregate service fractions. In a 24-hour correlated-outage/purge/attack-release scenario with 7106 sessions, both implementations have digest 1563cef9d43a8d5f2753cfa2a7ccf2ea7b0d4dc601b67b58659f1711da2a252b. There were 1,238,680 cache hits and two misses. Full-run wall timing was noisy under concurrent host activity, so it is not a reliable speed comparison. An interleaved 3600-second test gave plain 0.278/0.257 seconds and cached 0.172/0.172 seconds with identical full-result digests, approximately a 35% reduction in that test. The cache was applied only after approval and equality verification.

The final isolated core checks passed all fifteen regression tests and the original 43-check gate after memoization. git diff --check passed. The core is frozen for the new experiment batch; historical result files have not been rewritten.

The native Windows process failure could not be reproduced by this agent's stdlib, NumPy, simulator or actual-runner one-worker ProcessPool probes. The actual run_job completed a 24-hour scenario in 5.333 seconds and wrote only a diagnostic artifact under docs/revision/audit_tools/pool_probe_outputs. The root agent subsequently captured a concrete multiprocessing.spawn_main DuplicateHandle WinError 5 access-denied traceback in results/revision/pilot.stderr.log. This supports using independent shell-launched serial shards instead of the affected multiprocessing handle-duplication path. It does not implicate a statistical/model calculation. Diagnosis stopped at the root agent's request once that bounded workaround was selected.

The diagnosis was reopened when serial shards also failed. This agent reproduced exit -536870873 (0xe0000027) after the coordinator header, while the first uncached case/seed completed successfully through a logging wrapper in both a diagnostic output directory and the actual run directory. The root agent then isolated a deterministic trigger outside the simulator: `python -X faulthandler -u -c "import platform,time; print(platform.platform()); time.sleep(6); print('done')"`. This agent independently ran that exact command; it printed Windows-11-10.0.22631-SP0, exited with 0xe0000027 after 1.64 seconds, and never reached done. The runner's platform metadata call therefore explains the serial coordinator failure, independent of the separate multiprocessing handle error. Replacing that metadata lookup with non-WMI OS/version information is a targeted coordinator correction; no scientific core change is indicated. The earlier multiprocessing-only workaround was insufficient and is superseded by this direct evidence.
