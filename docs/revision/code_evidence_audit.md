# Code and evidence audit, 26 September 2026

This audit concerns the historical simulator at Git commit `0d1e2fa`, the submitted `paper.tex`, and the saved `results/` and `figures/`. The first inspection did not alter historical code, results, or manuscript. Subsequent corrective core work is explicitly described at the end. The historical CSVs remain historical evidence and must not be presented as results of the corrected simulator.

The important distinction is between internal arithmetic correctness, reproducing saved simulation results, and establishing that a model represents a deployed QKD network. The historical code succeeds at several internal checks and one exact replay. It does not have an independently validated physical/security model. Several substantive manuscript conclusions depend on untested semantics or on choices built into the simulator.

## Algorithms and experiment inventory

`physics.py` implements a normalized binary-entropy secret-key-rate shape, a hard engineering cutoff, link status, and a finite key inventory. `network.py` builds the formation and a two-path chain and selects bounded candidate paths. SP picks the first classically viable shortest candidate; KAR minimizes the largest hop refill wait plus a hop-count penalty. This is an in-house heuristic family, not a faithful reimplementation with checked parity against a named published routing algorithm. CAF protects fixed 20%/40% inventory fractions for lower-priority classes. `sim.py` advances in one-second ticks with independent arrival, endpoint, and outage RNG streams, strict priority then FIFO, transactional all-hop debit, and a grade fallback sequence. It is a discrete-time simulator, not a general event-queue simulator.

`rl.py` defines 12 observable cells (three traffic classes by four shortest-path occupancy buckets), five actions (G1–G4 or defer), and a C2-only deterministic shield. E7 searches categorical lookup tables using the cross-entropy method. This is a legitimate derivative-free policy search procedure with sequential rollouts; it is not neural RL, a learned physical model, or proof of policy optimality.

## Physics and security validity

The main material bug is that historical `_usable` required strictly positive current generation before allowing a quantum-grade relay. A fully stocked one-link path at QBER abort therefore cannot serve G2 even with 51,380,224 drawable bits and a working classical channel, but immediately serves G4. The read-only probe demonstrates this exactly. An abort concerns fresh-key generation; stored accepted keys should remain available unless the threat model explicitly invalidates them. No such retroactive compromise model exists. Thus historic attacks erase the service value of a buffer without consuming it. The dramatic immediate cut result and authentication-insensitivity under attack cannot be transferred unchanged to buffered relay semantics.

The formation contains eight nodes and nine links, not nine nodes. Each forward post has a single terminal edge, so the individual BASE-to-FWD minimum cut is one. The first two betweenness-ranked edges are BDE1–BDE2 and REL1–BDE1. Removing them leaves FWD3 reachable. Their two-edge cut isolates a particular two-post group, not every forward post and not a universal minimum cut. The single-terminal two-path chain has a minimum cut of two at depth at least two, which is valid graph theory but cannot rescue the formation wording. The function named `_mincut_order` concatenates per-terminal cuts; it does not solve optimal traffic-weighted multi-terminal interdiction. Its returned set edges were not sorted, which can change the prefixes used at small budgets.

The QBER formula collapses source yields, single-photon fractions and finite-key effects into a nominal rate and uses one error argument for both terms. It is a sensitivity surrogate, not a composable BB84/decoy-state security calculation. For f=1.16 the expression itself reaches zero near e=0.098, so an engineering cutoff of 0.11 does not move the true positive-rate boundary to 0.11. Any sensitivity claim that the injection boundary moves from 0.045 to 0.08 solely by raising e_abort ignores the earlier entropy zero. The exponent gamma=3.4 is fitted to one Tokyo degradation ratio and then checked against that same ratio: this is calibration reuse, not independent validation. A fibre/SARG04 Tokyo value is also labelled FSO_SHORT, mixing optical platforms into scenario parameters.

Four ordered grade labels encode an operator policy convention. G1 protects payload by OTP; G2 conveys a 256-bit key but protects payload computationally; G3 combines 128 quantum bits and ML-KEM; G4 uses ML-KEM. The implementation produces no actual keys, performs no KEM or combiner, tracks no epsilon security budget, and models no authenticity compromise, replay, downgrade negotiation, endpoint binding or relay compromise. It cannot prove cryptographic security or prevention of a real protocol downgrade. It can count compliance with specified grade contracts under trusted-relay assumptions.

The reserve is a fixed unavailable inventory floor. Periodic QKD post-processing authentication does not consume it. Therefore reserving it is not a tested continuity or authentication-availability guarantee. The accounting formula treats a relay transaction as demand + metadata + n_auth tags on each hop, with no fragmentation, aggregation, retransmission or partial-failure cost. Its exact local invariant is useful, but its default protocol interpretation remains assumed.

The attack budget is a count of persistently affected links at t=0, not energy, transmit power, money, duration, detection risk, or an optimized adaptive adversary. Outages are independent geometric processes in one-second steps; neither terrain correlation nor mobility, burst traffic, correlated pointing errors, repair constraints or setup recovery is modelled. `OutageConfig.grace_s` is not used. Classical bandwidth, authentication workload, congestion and route-dependent PQC latency are absent, which makes fail-degraded availability essentially classical reachability by construction whenever fallback is authorized.

## Validation provenance

No experimental dataset was collected from QKD hardware in this artifact. E8 is arithmetic over figures transcribed or derived from publications. It invokes only AccountingConfig; it does not run the simulator. V1 recomputes volume/rate and E1 loops the same arithmetic through KeyStore. The manuscript appropriately calls V1 internal consistency, but the abstract phrase about reproducing measurements is stronger than that evidence.

V4 divides a range of individual link rates by a bidirectional voice demand and accepts the eleven network-wide simultaneous calls because eleven lies in that broad range. It does not reproduce the measured network topology, routes, bottlenecks or call allocation. It is an order-of-magnitude plausibility bound, not validation of network capacity or control. The paper partly acknowledges this distinction.

V2 infers a roughly 400-bit global key, interprets about 180 kbytes as binary kbytes, and assumes a per-key per-hop unit from a multi-node deployment. Those uncertain transformations preclude treating its n_auth≈7 as an independently measured universal tag count. V3 compares a 512-bit-cipher application round with a 256-bit per-hop model. Its n_auth≈40 is obtained by assigning the full 5312-bit round overhead to one model transaction. If simply apportioned over two 256-bit keys, the same arithmetic would give about nineteen tags after subtracting one metadata term, before considering whether protocol authentication is shared. The mismatch exposes a missing protocol layer, not a precise universal calibration.

Consequently revised scenarios may transparently use n_auth=2,7,40 as an uncertainty sweep. Neither seven nor forty should be labelled an independently validated default. Keeping the default two solely for API compatibility is acceptable if the revised experiment chooses its value explicitly and does not claim lower-bound proof. The available code does not establish that no other simulator can validate any relevant component; impossibility claims about NetSquid/SeQUeNCe/QuISP are too broad. Their lack of a turnkey key-pool policy can explain why direct parity is unavailable, without precluding extensions or component-level cross-checks.

## ML evaluation and inference limitations

E7 trains on RNG seeds 0 and 1 and evaluates on 0 through 7. This overlaps realizations; the first training segment is a prefix of evaluation on those two seeds. Test seeds must be disjoint and frozen independently of model selection. A separate validation set is also required if choosing reward weights, search budgets, model variants or horizons after seeing test performance. The single optimizer seed per shield condition conflates shielding with search variability; paired optimizer seeds and comparable search budgets are needed.

The 6-hour training/3-hour warmup versus 24-hour evaluation/12-hour warmup produces a real distribution change, but the causal attribution to depletion is not established by that comparison alone. It also changes horizon, scored window, stochastic sampling, and the optimizer's realized state coverage. There are no saved per-cell visitation counts, storage trajectories, retraining-on-long-horizon control, independent initial-fill sweep, or matched-horizon ablation. The twelve-cell state ignores arrivals remaining, request deadlines, alternative-path health, key generation, attack state and time-to-depletion. Shortest-path occupancy may look healthy on an unusable route and does not describe relevant alternative routes. This is a partially observed controller; its failure is not a general result against learned routing.

The historical heuristic table is not the simulator's main grade controller: the table tries one grade per tick, whereas the main fail-degraded controller tries several weaker grades immediately. The table only selects fallback in its zero-available bucket, often unreachable because inventory rarely lands exactly on the reserve. Thus E7 does not compare the searched policy against precisely the E2/E3 heuristic. Its shield also maps a forbidden C2 action to G1, spending 2048 payload bits instead of the permitted 256-bit G2 key, an avoidable objective confound.

J combines arrival-denominator availability with served-denominator violation and ITS share. Selective blocking changes the latter denominators. Serving only strong-grade traffic can improve the conditional quality indicators while excluding other classes. The policy should instead be assessed with per-class arrival counts, timely authorized service, blocked service, and unauthorized service, plus payload-weighted assurance loss. Learned callbacks historically bypass FAIL_CLOSED entirely, so the name of the scenario does not guarantee its contract when a learned controller is attached.

The unshielded policy's high reward and 11x lower key consumption can be explained by replacing expensive ISR OTP with G2 while satisfying an objective that rewards ITS-delivered key. This is objective misalignment under intentionally permitted grade actions, not evidence that an adversary bypassed a cryptographic shield. A simple fixed G2 policy must be evaluated before attributing this pattern to discovery requiring AI. The unshielded final table is missing, so its exact behavior cannot be audited from the delivered policy artifact.

The lambda≈0.370 crossing is arithmetic between two fixed mean component vectors, not an optimized Pareto frontier. Because those means mix denominators, it is not directly the price of one downgrade versus one served session. It needs uncertainty estimates and explicit conditioning. The claim that search is uniquely needed to derive it is unsupported. A best-found sampled policy is not a global optimum, and a heuristic scoring 104.8% of its reward is not proof of near-optimality or limited headroom. Seven stress-condition mean wins have no stored seed-level intervals; one mean difference is about 0.0041, so significance cannot be assumed.

## Measurement and statistics

The historical warmup filter applies to service and grade fractions, but mean_hops and key/generated/discarded counters include the whole horizon. Consequently plotted key/availability pairs mix time windows. Claims that all metrics discard the first twelve hours are false. The pre/post comparison used to justify a twelve-hour warmup is not saved as trajectories; a fixed warmup cannot establish stationarity under every policy and demand condition.

G4 is recorded as served at t+0.35 without checking the request deadline. G3 uses the same KEM abstraction but historically receives no setup delay. The service loop tries serving before checking expiry, so a one-second-deadline request attempted at t=2 is served late. All pending requests at the horizon are then marked blocked even when their actual deadline remains in the future, creating right-boundary bias. All are directly reproducible in the audit probe or regression tests.

Paired seed-level bootstrap is appropriate for the common-random-number comparison under a fixed scenario; the independently recomputed main interval matches. It quantifies simulation-realization uncertainty, not uncertainty in physics, topology, accounting or traffic realism. Some reported SDs use population `np.std` and plots use pandas sample standard deviation, so labels should be standardized. E4 thresholds use mean forced share rather than a confidence-bounded crossing; three seeds cannot support fine uncertainty statements. Multiple exploratory comparisons are not multiplicity-adjusted and should be described as exploratory rather than confirmatory significance tests.

The separate RNG streams correctly preserve arrivals and channel realizations when changing only policy within the same fixed graph/traffic configuration. They do not guarantee matched stochastic traces after changing topology size, traffic mix, or which links skip RNG draws under classical denial. A stronger revision can pre-generate immutable exogenous traces shared across policies, with independent scenario, optimizer, validation and test IDs.

## Figures and historical document contradictions

The figure scripts are driven by saved CSVs for fail mode, grade mixture, forcing cost, routing/key tradeoffs, overhead and policy audit. They use secondary style encodings and vector PDF output, which is useful for print. The submitted manuscript references only architecture and forcing-cost figures. The architecture draws the actual eight nodes but labels a two-edge terminal-group cut as a minimum cut. It should distinguish the affected group and surviving terminal.

The policy-audit figure contains aggregate bars without uncertainty because per-seed data were not retained. Routing/key plots inherit the mixed measurement windows. Sensitivity plots must mark the actual zero of the rate model, not only configured e_abort, and should not present model-defined thresholds as empirically discovered laws. This audit inspected figure generation code and file presence; it did not undertake visual or accessibility certification of the PDF render.

RESULTS.md still calls 39.5% floor violations forced downgrades in E7 and states a six-seed E4 run despite the three-seed CSV. PHASE2_DESIGN.md calls baselines reproduced, promises pinned versions/config dumps and a cross-check, but the shipped code does not satisfy all of those promises. PROJECT_HANDOFF and FINAL_IMPROVEMENT_REPORT contain planning statements superseded by later files and unsupported acceptance predictions. They should remain historical notes, with the revised paper and manifest designated authoritative. The 38-check numeric script explicitly sets the training J values' actual argument to None, so its pass does not verify those numbers.

## Most defensible new contribution and decisive experiments

A practical contribution is an auditable benchmark of contract-preserving learned control for finite QKD key inventories under disruptions, paired with a controller that observes resource depletion and enforces each class's assurance contract before scheduling. This can preserve substantive AI/ML while moving beyond a graph cut that follows from the model. Whether a particular proposed controller is novel requires current literature review; this code audit does not establish firstness.

The decisive comparison is against fixed floor/defer, strict-priority, reserve-aware and backlog/deadline-aware baselines using identical admission and routing semantics, a fixed total search budget, disjoint training/validation/test scenario seeds and multiple optimizer seeds. Hold out topology, initial fill, load, outage correlation and attack timing; repeat matched horizon and fill conditions to isolate the transient mechanism. Publish raw per-seed/per-class arrival outcomes, state visitation, inventory trajectories, both raw and executed policies, and effect-size intervals. Negative ML results remain scientifically useful if those controls rule out easy alternatives.

An analytically useful companion is a finite-horizon inventory/cut capacity bound: accepted stock plus cumulative replenishment limits the demand that can cross a classical-reachable cut before its deadline. It should distinguish generation disruption from transport disconnection. A policy may be compared with the bound or a small-instance exhaustive oracle; neither is an assertion of global optimality. Small deterministic examples, all-hop conservation, zero-generation/full-stock, depleted/connected, outage/recovery, and exact-deadline cases provide stronger independent verification than reproducing fitted constants.

## Corrective implementation status

Following the baseline audit, the root agent authorized core corrections. Version 0.2.0 separates generation from transport, retains stocked key through ABORT, enforces deadline completion including G3/G4 setup, enforces fail-closed floors even for callbacks, provides optional all-class shielding with floor projection, fixes cache argument keys and deterministic cut edge ordering, and gives the topology an accurate eight-node name with the old name retained as an alias. Historical source is recoverable at commit 0d1e2fa; historical CSVs have not been regenerated.

`tests/test_revision_core.py` was written first. Its initial run produced fifteen expected failing assertions across fourteen tests, with the existing physical-outage case passing. After implementation, `python -m unittest discover -s tests -v` passed all fourteen tests. The original `python experiments/e1_validation.py` also continued to pass all 43 checks. The new regression suite verifies the defects the old gate did not cover; it is not a hardware validation claim.

Results now expose `outcome_metrics(cls=None)` with explicit per-arrival numerators, denominators and payload totals. `consumed_bits` uses the arrival cohort; generation and discarded bits use the fixed measurement event window; full counters and boundary inventory support conservation. Pending requests are allowed to resolve to their actual deadlines after arrivals stop. The detailed interface is documented in `core_measurement_semantics.md`.

A fifteenth regression was subsequently added and observed failing before correcting full-run counters to exclude pre-run inventory operations. The targeted final core command is `python -m unittest discover -s tests -p test_revision_core.py -v`, so concurrent development of other revision tests cannot obscure core status.

A corrected 24-hour seed-0 fail-closed run at k=2, n_auth=2 took 5.388 seconds of simulation time. Its measured arrival-cohort availability is 0.767877541695225, with C2 0.9235347985347986 and ISR 0.06192660550458716, zero floor violations, and zero full-run/window conservation residuals. This one-run diagnostic is not a revised multi-seed result. It demonstrates that keeping accepted stored keys available materially changes the historical approximately 0.304 availability headline and therefore necessitates new experiments.
