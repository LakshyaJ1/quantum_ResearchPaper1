# Corrected core interface and measurement contract

This describes qkdsim version 0.2.0. Saved historical `results/*.csv` belong to version 0.1.0 at Git commit 0d1e2fa. Do not silently mix those results with new output. New experiments should write to a separate revision directory and store full configurations, code hash, dependency versions, seeds and raw rollout rows.

`formation_8node(reservoir)` is the accurate formation name. `formation_9node` remains an alias to avoid breaking historical imports. The graph has eight nodes and nine links. Each individual forward node has a one-edge source-to-terminal cut. A two-edge cut around one brigade group is a different object.

ABORT produces no fresh key. It does not invalidate accepted key already in the store. Quantum-grade relaying can use that stock when the classical path works and every hop can pay its debit above the reserve. OUTAGE blocks classical transport as well as generation but retains stored keys for later recovery. If a path has no refill and insufficient stock, KAR treats its wait as infeasible. A full store on a zero-rate link remains usable. Source compromise and retroactive key invalidation are outside this model.

`FAIL_CLOSED` is enforced in `_try_grade`, including externally supplied grade policies. A callback requesting a grade below the request's authorised floor is refused and may retry later. `Shield(all_class_floors=True)` masks below-floor actions for every class; the default `all_class_floors=False` retains the named C2-only ablation. An invalid action is projected to the weakest allowed grade rather than needlessly paying for G1. DEFER remains permitted. The shield guarantees the specified grade condition; it does not guarantee availability, cryptographic implementation correctness or a security epsilon.

G3 and G4 use `pqc_setup_s`; their completion time must fit the request deadline before any key debit. G1/G2 have zero modelled setup delay. A request can complete exactly at its deadline, but not after it. Setup is an abstract deterministic completion delay, without packet-level link failures during the setup interval. Arrivals occur only while t < horizon_s. At the horizon the simulator stops admitting arrivals and continues the environment until every pending request is served or has expired. This avoids labelling right-censored requests as blocked. The maximum extra duration is bounded by request deadlines.

The outcome cohort is requests with warmup_s <= arrival_t < horizon_s, including a cohort request served during the deadline drain. `served_fraction`, `blocked_fraction`, grade composition, conditional legacy violation metrics, time-to-key and mean hops all use this cohort. Legacy methods such as `floor_violation_fraction` retain their documented served-request denominators for compatibility. Use `outcome_metrics` for revised performance claims.

`outcome_metrics(cls=None)` reports n_arrivals, n_served, n_timely_served, n_blocked, n_pending, n_authorized_served, n_floor_violations, n_its_entitled and n_forced_below_its. Here authorized means timely and at least the contractual grade; forced below ITS means entitled to G1/G2 but actually served at G3/G4. All `*_arrival_fraction` keys divide by n_arrivals for that selected class or cohort. `forced_below_its_entitled_arrival_fraction` instead divides by all eligible G1/G2 arrivals, including those blocked. A zero denominator returns NaN, not a misleading zero.

The same method returns payload_bits_total, payload_bits_served, floor_violation_payload_bits, forced_below_its_payload_bits, payload_its_bits (G1) and cohort_key_bits. Payload volume below the contract is not a measurement of actual plaintext disclosure. G2 uses computational payload encryption despite the model's ITS-delivered key label. Use counts and these fields to show both command/OTP entitlement and service outcomes rather than combining incompatible security dimensions.

`consumed_bits` and outcome_metrics.cohort_key_bits sum all hop debits for the measured arrival cohort. `generated_bits` and `discarded_bits` refer to events with tick time in [warmup_s, horizon_s). `window_consumed_bits` uses that same event window; it may include a pre-warmup request served after warmup and excludes a measured request served during the post-horizon drain. Consequently cohort consumption must not be put into the event-window conservation identity.

The event identity is window_initial_stored_bits + generated_bits - window_consumed_bits - discarded_bits = window_final_stored_bits. The full-run identity is initial_stored_bits + full_generated_bits - full_consumed_bits - full_discarded_bits = final_stored_bits. Full counters measure changes since run() starts, include warmup and deadline drain, and agree with total store counters for a fresh topology. Inventory preparation before run() is part of initial_stored_bits, not new run activity. Floating tolerances are required if noninteger rates are used. link_state_ticks currently counts all run ticks including warmup and drain; it must be labelled accordingly, not represented as a measurement-window fraction.

cfg_summary includes a complete nested dataclass config and a semantic version label. It cannot capture arbitrary external subclass behavior or callback source. Experiment manifests must additionally record controller type/configuration, trace/scenario provenance, topology construction, source hash and any environment subclass parameters.

The historical n_auth default of two is retained to keep the original API usable. Revised scenarios should explicitly set seven as a chosen central sensitivity setting if desired and compare two/forty without claiming those values are universally measured or validated. The old E7 effective-table postprocessor remains a historical utility: its hard-coded G1 projection is not the executed v0.2.0 shield.
